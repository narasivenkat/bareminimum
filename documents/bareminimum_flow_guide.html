01. Flow Overview & Key Principles

The BareMinimum Agentic Coding Harness operates as a deterministic, state-aware execution engine. Unlike naive agent loops that naively append messages and perform unbounded tool executions, BareMinimum enforces a strict, governed state flow designed for high-performance software engineering tasks.

⚡ Parallelized Tooling

Read-only file system operations (list_dir, read_file, file_search, graph_retrieve) are dispatched concurrently via worker threads to eliminate network/I/O bottlenecks.

💬 Mandatory Narration

Every tool execution must be preceded by a short plain-text narration sentence explaining the intent behind the call, guaranteeing transparent audit trails.

🛡️ Governance Sandbox

File path traversal checks (workspace_guard.py) and tool output sanitization (tool_output_sanitizer.py) shield the workspace against escape and prompt injections.

Core Execution Pipeline Summary

CLI Entry Flag Parsing & Configuration → LLM Client Initialization → Context Compaction Gatekeeper → Reasoning Generation → Plain-Text Narration Check → Tool Security Guard → Parallel Read / Mutex Write Execution → State Update & Token Accounting → Final Answer Synthesis.

03. Control Loop Core (`loop/loop.py`)

The core execution heartbeat is governed by BareMinimumLoop.run() in loop/loop.py. It manages iteration bounds, token tracking, tool execution, and context retention.

Step 1: System Prompt & Conversation Context Assembly

Constructs initial prompt payload including the mandatory system prompt (from prompts/system_prompt.py) which specifies narration rules, tool signatures, and security constraints, combined with the user's objective.

Step 2: Context Window Compaction Assessment

Before calling the LLM, compaction.py inspects total token count using local tiktoken encoding. If usage exceeds the compaction trigger limit, sliding window truncation and mid-conversation summarization automatically compress early turns.

Step 3: LLM Inference Request

Invokes llm/llm_client.py with full conversation context and function signatures. Dual-stream tracking registers both tiktoken local estimates and exact provider API usage metadata.

Step 4: Tool Call & Narration Parsing

Extracts tool call proposals and assistant message text. Checks if the response contains valid tool calls or signals final task completion (lack of tool calls).

Step 5: Governance Verification & Tool Dispatch

Routes read tools to parallel worker threads and write tools to sequential execution under path traversal inspection. Tool outputs are sanitized and appended to the context.

Step 6: Completion / Next Turn Evaluation

If LLM returns a plain-text message without tool calls, the loop terminates and returns an AgentResult containing token totals, cost estimations, timing metadata, and final response.

04. Narration Requirement Flow

To eliminate "blind tool calls" and ensure full auditability, BareMinimum enforces a system-level constraint: Every tool call must be accompanied by plain-text narration in the message content.

Narration Rule Spec

"Whenever you call a tool, you MUST also write one short narration of plain text in the message content that narrates why you want to use the tool for (example: 'Reading loop.py to inspect the agent loop.'). Do not emit a tool call with empty narration."

05. Governance & Safety Interception

Every tool request and file path passes through governance guards prior to execution on the physical system.

Security Component Target File Functionality & Policy Enforced
WorkspaceGuard governance/workspace_guard.py Resolves real canonical file paths using os.path.realpath() to ensure target files remain within workspace root. Blocks directory escape attacks (e.g. ../../etc/passwd).
ToolOutputSanitizer tools/tool_output_sanitizer.py Inspects retrieved file contents and command outputs for indirect prompt injection vectors, hidden control characters, or malicious prompt hijacking directives.
HITL Approver tools/registry.py Forces interactive confirmation and generates unified dry-run diff previews prior to executing file modifications or deletions (write_file, delete_file).

To maximize efficiency during codebase exploration, BareMinimum categorizes tools into Concurrent Read Operations and Mutex-Locked Write Operations.

07. Context Management & Compaction Lifecycle

As interaction history grows, context token usage is continuously tracked via local tiktoken calculation alongside API response token headers.

Compaction Thresholds

When current context tokens reach 80% of model capacity (or explicit token limit), memory/compaction.py triggers automated context window compression.

Context Preservation Hierarchy

1. System Prompt (Always Kept)
2. Original User Task (Always Kept)
3. Compressed Summary of Intermediate Turns
4. Recent Conversation Buffer (Kept Intact)

08. Multi-Agent Orchestration Flow

In --mode orchestrator, BareMinimum leverages Microsoft AutoGen to delegate complex tasks across specialized sub-agents.

🤖 UserProxyAgent (Orchestrator)

Receives user request, breaks task down into sub-goals, coordinates sub-agents, and synthesizes final result.

🔍 ExplorerSubAgent

Dedicated inspection agent equipped with asynchronous read tools (async_read_file, async_list_dir, async_graph_retrieve).

✏️ WriterAgent

Dedicated code modification agent equipped with mutex-locked write tools (async_write_file, async_delete_file).
