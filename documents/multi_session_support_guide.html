BareMinimum Multi-Session Support Analysis & Architectural Guide

Current State: Single Session / Single Task Target State: Production Multi-Session Engine Architecture & Design

Executive Summary

This document answers two fundamental engineering questions regarding the BareMinimum Agentic Coding Harness:

  1. Can BareMinimum currently handle a single session or multiple sessions?
  2. How can BareMinimum be refactored and scaled to support multiple concurrent and persistent sessions?

Core Finding: Current Capability Is Single Session (Task-Bounded REPL)

In its current architecture, BareMinimum only supports a single interactive session per process execution. Conversation history is held strictly in ephemeral memory during a single agent task run (run_agent() in loop/loop.py). There is no session identification, session storage engine, multi-tenant directory isolation, or concurrent thread safety mechanism.

To enable multi-session capability (supporting multiple user conversations simultaneously, restoring past sessions, and isolating workspaces), BareMinimum requires four core architectural additions:

  • Session Context Model & Identifier: Explicit session_id and user_id bindings for state scoping.
  • Persistent Session Store: Disk/Database serialization (e.g. SQLite or JSON files in .bareminimum/sessions/) for turn-by-turn history.
  • Thread-Safe Session Manager: An async session lifecycle manager handling session creation, switching, concurrency locks, and resource cleanup.
  • Workspace Sandboxing & Multi-Tenant Isolation: Virtualized relative path resolution and workspace locking per session.

1. Current Capabilities Analysis

A comprehensive review of the current BareMinimum codebase reveals the exact scope and boundaries of its session handling:

Module / File Current Implementation Session Scope
run.py CLI entrypoint with interactive while True loop and single active model context (active_model). Single process lifecycle; commands run in series for one operator.
loop/loop.py run_agent() builds a local messages = [] list that lasts only for the duration of a single user prompt loop. Task-bound / Ephemeral. Cleared on each task completion or script exit.
orchestrator/orchestrator.py AutoGen orchestrator spawns sub-agents to process parallel read tasks and serialized write tasks for a single turn. Single-request thread pool without session routing.
memory/compaction.py MemoryCompactor compacts the local messages list when context threshold is exceeded. Operates only on in-memory lists within a single task run.
config/config.py Loads workspace root from environment variable (HARNESS_WORKSPACE) or process current working directory (os.getcwd()). Process-global single workspace root.
graph/dbconn.py Singleton/shared Neo4j connection pool executing cypher queries globally across the code graph. Global graph access; lacks tenant/session namespace tags.

Why Current BareMinimum Is Single Session

When a user executes python run.py, the system enters a single CLI input loop. Each user entry invokes run_agent(prompt, model, tools). Inside run_agent: 

# Inside loop/loop.py (Current implementation)
def run_agent(user_prompt: str, model: Any, tools: ToolRegistry, ...):
    messages: List[Dict[str, Any]] = []  # <--- Fresh list created every run!
    messages.append({"role": "user", "content": user_prompt})
    
    # Executed until completion...
    return AgentResult(...)

Because messages is created anew on each prompt invocation (or stored only in memory during a single CLI session without persistent indexing or multi-user keying):

  • No Session Persistence: Context is lost once the process exits or when switching tasks.
  • No Concurrent Session Support: Two simultaneous requests will collide on process resources, workspace writes, and global state variable active_model.
  • No Multi-Tenancy: File operations operate directly on a single shared workspace root without user or session boundaries.

2. Architectural Gap & Bottlenecks

To transition BareMinimum from a single-session CLI tool into a multi-session enterprise agent framework, four main technical gaps must be addressed:

1. State Coupling Gap

Global variables (active_model, process cwd) prevent multiple sessions from running with different model configs or in different working directories simultaneously.

2. Storage & Memory Gap

No storage adapter exists to load, save, or compact session state to disk or database (SQLite/JSONL) across process restarts or client disconnects.

3. Workspace Conflict Gap

Parallel session file operations will trigger race conditions and file corruption without a per-session write lock manager or per-session workspace sandboxes.

4. Routing & Transport Gap

Current interface is limited to stdin/stdout CLI. Multi-session requires asynchronous transport (REST API / WebSockets) with session headers or CLI session switching commands.

4. Step-by-Step Implementation Blueprint

To make BareMinimum handle multiple sessions cleanly without breaking existing single-turn behavior, implement the following steps:

Step 1: Define the Core Session Data Structure

Create a Session class encapsulating conversation history, token telemetry, user settings, and execution locks:

  • session_id (str): Unique UUID or slug identifier (e.g. sess_20250330_a9f1).
  • user_id (str): Tenant or user identifier for auth and quota isolation.
  • model_name (str): Model configured for this specific session (e.g., gpt-4o, claude-3-5-sonnet).
  • messages (List[Dict]): Historical message list for multi-turn conversations.
  • workspace_path (Path): Directory scope reserved for this session.
  • token_usage (Dict): Session-accumulated token count and financial cost.
  • lock (asyncio.Lock): Prevents concurrent turn execution within the same session ID.

Step 2: Build a Session Persistence Layer (SessionStore)

Implement a store that saves and retrieves session states to/from disk (or a relational database). Store session data in JSON/JSONL format under .bareminimum/sessions/{session_id}.json.

Step 3: Refactor Control Loop to Accept Session Context

Refactor run_agent() in loop/loop.py into a session-aware function run_agent_session() that takes a Session object, appends new user inputs to the session history, runs compaction on that session's history, and persists state after completion.

Step 4: Create a Central SessionManager

Implement a singleton/manager class that maintains in-memory active sessions, loads dormant sessions from storage, handles timeout eviction, and provides thread-safe operations.

Step 5: Provide Multi-Session Interfaces (CLI & REST/WebSocket API)

Extend the CLI with /session subcommands (create, list, switch, delete) and add a FastAPI server endpoint allowing multi-tenant HTTP/WebSocket clients to pass a X-Session-ID header.

5. Concrete Code Implementation Specs

Below is the complete architectural implementation code ready for inclusion into BareMinimum:

A. Session Store Module (session/store.py)

import json
import os
from pathlib import Path
from typing import Dict, Any, Optional, List
from dataclasses import dataclass, field, asdict
import time

@dataclass
class SessionState:
    session_id: str
    user_id: str = "default_user"
    model_name: str = "gpt-4o"
    workspace_path: str = "."
    created_at: float = field(default_factory=time.time)
    updated_at: float = field(default_factory=time.time)
    messages: List[Dict[str, Any]] = field(default_factory=list)
    total_tokens: int = 0
    total_cost: float = 0.0
    metadata: Dict[str, Any]] = field(default_factory=dict)

class SessionStore:
    """Persistent storage engine for BareMinimum sessions."""
    
    def __init__(self, storage_dir: str = ".bareminimum/sessions"):
        self.storage_dir = Path(storage_dir)
        self.storage_dir.mkdir(parents=True, exist_ok=True)

    def _get_path(self, session_id: str) -> Path:
        return self.storage_dir / f"{session_id}.json"

    def save_session(self, session: SessionState) -> None:
        """Persist session state to JSON file."""
        session.updated_at = time.time()
        file_path = self._get_path(session.session_id)
        temp_path = file_path.with_suffix(".tmp")
        
        with open(temp_path, "w", encoding="utf-8") as f:
            json.dump(asdict(session), f, indent=2, ensure_ascii=False)
        temp_path.replace(file_path)

    def load_session(self, session_id: str) -> Optional[SessionState]:
        """Load session state from JSON file."""
        file_path = self._get_path(session_id)
        if not file_path.exists():
            return None
        with open(file_path, "r", encoding="utf-8") as f:
            data = json.load(f)
        return SessionState(**data)

    def list_sessions(() -> List[Dict[str, Any]]:
        """List summary of all persisted sessions."""
        sessions = []
        for p in self.storage_dir.glob("*.json"):
            try:
                with open(p, "r", encoding="utf-8") as f:
                    data = json.load(f)
                    sessions.append({
                        "session_id": data.get("session_id"),
                        "user_id": data.get("user_id"),
                        "model_name": data.get("model_name"),
                        "updated_at": data.get("updated_at"),
                        "message_count": len(data.get("messages", [])),
                    })
            except Exception:
                continue
        return sorted(sessions, key=lambda s: s.get("updated_at", 0), reverse=True)

    def delete_session(self, session_id: str) -> bool:
        """Delete session persistence file."""
        file_path = self._get_path(session_id)
        if file_path.exists():
            file_path.unlink()
            return True
        return False

B. Session Manager Engine (session/manager.py)

import asyncio
import uuid
from typing import Dict, Optional, List
from session.store import SessionStore, SessionState
from memory.compaction import MemoryCompactor

class SessionManager:
    """Thread-safe manager controlling concurrent session lifecycles."""

    def __init__(self, store: Optional[SessionStore] = None):
        self.store = store or SessionStore()
        self._active_sessions: Dict[str, SessionState] = {}
        self._locks: Dict[str, asyncio.Lock] = {}
        self._global_lock = asyncio.Lock()

    async def get_or_create_session(
        self, 
        session_id: Optional[str] = None, 
        user_id: str = "default_user",
        model_name: str = "gpt-4o",
        workspace_path: str = "."
    ) -> SessionState:
        """Retrieve existing session or instantiate a new one."""
        async with self._global_lock:
            if not session_id:
                session_id = f"sess_{uuid.uuid4().hex[:8]}"

            if session_id in self._active_sessions:
                return self._active_sessions[session_id]

            # Try loading from persistence
            loaded = self.store.load_session(session_id)
            if loaded:
                self._active_sessions[session_id] = loaded
                if session_id not in self._locks:
                    self._locks[session_id] = asyncio.Lock()
                return loaded

            # Create new session
            new_session = SessionState(
                session_id=session_id,
                user_id=user_id,
                model_name=model_name,
                workspace_path=workspace_path
            )
            self.store.save_session(new_session)
            self._active_sessions[session_id] = new_session
            self._locks[session_id] = asyncio.Lock()
            return new_session

    def get_lock(self, session_id: str) -> asyncio.Lock:
        """Get per-session asyncio Lock for sequential turn execution."""
        if session_id not in self._locks:
            self._locks[session_id] = asyncio.Lock()
        return self._locks[session_id]

    async def save_session_state(self, session: SessionState) -> None:
        """Persist session updates to disk."""
        self.store.save_session(session)

    async def list_all_sessions(self) -> List[Dict[str, Any]]:
        """List active and saved sessions."""
        return self.store.list_sessions()

C. Refactored Session-Aware Agent Loop (loop/loop.py)

# Refactored agent turn execution accepting SessionState context
async def run_agent_session_turn(
    session: SessionState,
    user_input: str,
    tools: ToolRegistry,
    manager: SessionManager,
    compactor: Optional[MemoryCompactor] = None
) -> AgentResult:
    """Execute a single multi-turn interaction for a specific session."""
    session_lock = manager.get_lock(session.session_id)
    
    async with session_lock:
        # 1. Append new user prompt to session history
        session.messages.append({"role": "user", "content": user_input})
        
        # 2. Compact history if token budget exceeded
        if compactor:
            session.messages = compactor.compact(session.messages)
            
        # 3. Instantiate model with session's designated model config
        model = make_llm_model(session.model_name)
        
        # 4. Execute standard loop pass over accumulated session.messages
        result = await execute_loop_pass(
            messages=session.messages,
            model=model,
            tools=tools,
            workspace_root=session.workspace_path
        )
        
        # 5. Append assistant result & telemetry to session
        session.messages.append({"role": "assistant", "content": result.final_text})
        session.total_tokens += (result.input_tokens + result.output_tokens)
        session.total_cost += result.total_cost
        
        # 6. Save updated session state to disk
        await manager.save_session_state(session)
        
        return result

current_session_id = "sess_default"

while True:

            for s in sessions:

            current_session_id = new_sess.session_id
            print(f"Created and switched to new session: {current_session_id}")

7. Security, Sandboxing & Concurrency

When enabling multiple concurrent sessions, security and workspace boundary enforcement become critical:

Multi-Session Challenge Architectural Risk BareMinimum Solution
Workspace Collision Two sessions writing to the same file simultaneously could corrupt code or overwrite user changes. Workspace Sandboxing: Assign each session a dedicated subdirectory (e.g., /workspaces/{session_id}/) or virtual path sandbox.
Cross-Session Data Leakage Session A retrieving conversation memory or tool outputs belonging to Session B. Strict Context Isolation: Session state objects are isolated by UUID keys and passed explicitly down the call stack.
Graph RAG Tenant Mixing Cypher graph searches returning AST nodes across multi-tenant boundaries. Tenant-Tagged Graph Queries: Append WHERE n.tenant_id = $tenant_id to Cypher queries in graph/dbconn.py.
Resource Starvation / Spikes One session issuing high-frequency tool calls and starving CPU or LLM rate limits. Per-Session Rate Limiter: Token bucket and circuit breaker configured per session_id.

8. Adoption Roadmap & Conclusion

BareMinimum can be seamlessly upgraded from a single-session engine into a robust multi-session platform in 4 incremental phases:

Phase 1: Core Session Model & Persistence

Implement SessionState and SessionStore. Add JSON persistence under .bareminimum/sessions/.

Phase 2: Refactor Agent Loop

Update loop/loop.py to accept session context and maintain multi-turn history across runs.

Phase 3: CLI Session Commands

Add /session list, /session switch, /session new to run.py.

Phase 4: API Gateway & Sandboxing

Expose FastAPI REST/WebSocket endpoints and enforce per-session workspace sandboxing.

Conclusion

Currently, BareMinimum operates as a single-session CLI agent. However, by introducing the SessionManager, file-based persistence, per-session locking, and workspace sandboxing detailed in this guide, BareMinimum can easily be upgraded into a production-ready, multi-tenant agent harness capable of handling arbitrary concurrent client sessions.
