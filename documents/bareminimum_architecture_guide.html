BareMinimum Harness Architecture & Engineering Guide

Comprehensive technical specification and architectural manual for the BareMinimum Agentic Coding Harness—a high-performance, workspace-bounded AI coding agent engine designed for precision, velocity, and enterprise governance.

Architecture Spec v2.4 Workspace Bounded Token Compacted Parallel Orchestrator Graph RAG Enabled

1. Executive Overview

The BareMinimum Agentic Coding Harness is a lightweight, ultra-focused runtime designed to execute complex software engineering tasks. Built to overcome the bloating, high latency, and security vulnerabilities of traditional agent frameworks, BareMinimum enforces strict boundaries, determinism, and minimal token waste.

Unlike monolithic agent frameworks that load bloated prompts and unconstrained toolsets, BareMinimum operates with a targeted, workspace-isolated tool registry, dynamic history compaction, multi-provider LLM failover, and Human-in-the-Loop (HITL) safeguards.

Minimal Token Surface

Enforces target-first single-file reading, sliding-window history compaction, and XML tool payload encapsulation to keep prompt usage within optimal token windows.

Workspace Isolation

All file system mutations (reads, writes, deletes, listing, searches) are strictly confined to the project workspace root with path sanitization and directory traversal blocking.

Human-in-the-Loop (HITL)

Mutating operations (`write_file`, `delete_file`) generate interactive unified diff previews with explicit confirmation gates (`y/N`) and dry-run preview capabilities.

Hybrid Multi-Agent Parallelism

Integrates AutoGen Explorer agents to dispatch read operations in parallel while serializing write operations behind async mutex locks for zero code corruption.

2. Core Philosophy & Guiding Principles

BareMinimum was architected around four core design tenets:

  1. Laser-Sharp Context Efficiency: Do not flood the LLM prompt with entire source trees. Request exact line bounded windows, utilize file search wildcards, and compact old turn histories before token limits trigger performance degradation.
  2. Fail-Safe Workspace Confinement: The agent cannot escape the designated workspace directory. Paths containing directory traversal syntax (e.g., ../..) or external absolute paths are rejected.
  3. Transparent Governance & Auditability: Every tool execution, prompt injection check, token calculation, and model invocation is logged with microsecond accuracy to structured JSON logs.
  4. Model-Agnostic Model Interoperability: Seamlessly switch between Gemini 3.6 Flash, Claude Opus 4.8, DeepSeek V4.1 Flash, and GLM 5.3 Flash without altering business logic or tool schemas.

4. Control Loop Engine (`loop/loop.py`)

The control loop is the core driver of the agent runtime. It implements an iterative evaluate-and-execute state machine:

  • Loop Initiation: Accepts system instructions, initial user prompts, tool registries, and configuration overrides.
  • Iterative Cycle:
    1. Calculates total current context tokens using memory.token_counter.
    2. Triggers memory.compaction.compact_history() if total prompt tokens exceed the configured threshold (e.g., 70% of model window).
    3. Dispatches prompt and tool specifications to llm/llm_client.py.
    4. Parses assistant response: if text only, returns final result; if tool call requested, routes to ToolRegistry.dispatch().
    5. Sanitizes tool output via sanitize_tool_output() and appends result as a tool message in turn history.
    6. Checks maximum turn limit (AGENT.MAX_TURNS, default: 30 turns).
💡 Performance Metric Tracking (`AgentResult`)

Every execution loop returns an AgentResult object encapsulating total prompt tokens, total completion tokens, wall-clock latency, total turns taken, and tool invocation count for full operational visibility.

# Architectural snippet of the Core Loop Dispatch
class AgentLoop:
    def run(self, user_prompt: str) -> AgentResult:
        self.history.append({"role": "user", "content": user_prompt})
        
        for turn in range(self.max_turns):
            # Token limit & compaction check
            if self.should_compact():
                self.history = compact_history(self.history, max_tokens=self.context_threshold)
            
            response = self.llm_client.completion(messages=self.history, tools=self.registry.get_schemas())
            
            if not response.has_tool_calls():
                return AgentResult(status="SUCCESS", output=response.content, turns=turn + 1)
                
            for tool_call in response.tool_calls:
                result = self.registry.dispatch(tool_call)
                sanitized_result = sanitize_tool_output(result.content, path=result.path)
                self.history.append({"role": "tool", "tool_call_id": tool_call.id, "content": sanitized_result})
                
        raise MaxTurnsExceededException("Agent failed to settle within turn budget.")

5. Configuration & Launchers (`config/`, `runmin`)

BareMinimum features a unified configuration manager and cross-platform bootstrapping wrapper:

ConfigManager (`config/config.py`)

Centralizes configuration settings using hierarchical resolution:

  1. Environment Variables (e.g. BAREMINIMUM_DIR, HARNESS_WORKSPACE, DEFAULT_MODEL).
  2. Local YAML File (resources/config.yaml).
  3. Hardcoded Safety Defaults.

CLI Bootstrapping & Launchers

  • runmin.sh / runmin.bat: Environment bootsrapping shell scripts that automatically locate Python 3.10+, create/activate local .venv, install dependencies, export workspace paths, and execute run.py.
  • run.py: Entry point supporting single CLI prompt execution or interactive REPL. Includes built-in slash commands:
    • /bash <command>: Direct shell execution within workspace context.
    • /model [model_name]: Hot-switch current model provider at runtime.
    • /orchestrator: Toggle parallel sub-agent multi-processing.
    • /clear: Reset current conversation history.

6. Tool Subsystem & Workspace Boundaries (`tools/`)

Tools in BareMinimum are declared with OpenAI-compatible function calling schemas and registered in tools/registry.py. The registry handles tool resolution, alias mapping, parameter validation, and execution error wrapping.

Tool Name Aliases Access Mode Description
read_file — Read-Only Reads file content with optional 1-based line ranges (start_line, end_line).
write_file create_file Mutating / HITL Creates or updates file content. Generates diff preview & triggers HITL confirmation.
delete_file remove_file, unlink, delete Mutating / HITL Deletes specified file or recursive directory with user approval.
list_dir — Read-Only Lists directory contents. Appends / for subdirectories.
file_search search_files, glob_search Read-Only Matches files matching glob/wildcard patterns (e.g., *.py, **/*.json).
🔒 Workspace Sandboxing Guarantee

Every file path provided by an incoming tool call is resolved against HARNESS_WORKSPACE via os.path.abspath. If the resulting path falls outside the root directory, execution is immediately blocked with a PermissionError.

7. Security, Prompt Injection & HITL Safeguards

Security in BareMinimum is multi-tiered, protecting both the developer's filesystem and the LLM's prompt integrity.

1. Tool Output Sanitizer (`tools/tool_output_sanitizer.py`)

Files read from disk may contain untrusted text or malicious prompt injection instructions designed to override system instructions (e.g. "ignore all previous instructions"). The sanitizer protects the system by:

  • Encapsulating file content inside strict XML tags: <untrusted_file_content path="...">.
  • Escaping internal closing tags so content cannot break out of its XML boundaries.
  • Scanning content against regular expressions for prompt injection patterns. When detected, prepends a [SECURITY WARNING: Possible prompt injection detected] banner.

2. Human-in-the-Loop (HITL) Gate & Diff Engine

To prevent unintended modifications, all file modification requests undergo preview and approval:

  • Unified Diff Preview: Computes standard difflib.unified_diff comparing disk content vs target content.
  • Interactive Approval Prompt: Displays colored diff output in terminal and requests approval (Proceed with write? [y/N]).
  • Dry-Run Mode: Supports dry_run=True tool flag to generate diffs without writing to disk.
  • Async Mutex Locking: Mutating operations acquire _write_lock to prevent concurrent sub-agent file collisions.

8. AutoGen Sub-Agent Orchestrator (`orchestrator/`)

For complex tasks requiring parallel code exploration across multiple directories, BareMinimum leverages Microsoft AutoGen in a specialized hybrid dispatch model:

Parallel Read Fan-Out

Read operations (list_dir, read_file, file_search) are assigned to AutoGen Explorer Sub-Agents and executed concurrently using asyncio.gather and ThreadPoolExecutor.

Serialized Mutex Writes

All write and delete operations are routed to a single Writer Agent backed by an asyncio.Lock() write queue, ensuring strict linear order and atomic modifications.

# Orchestrator concurrency & mutex pattern (orchestrator/tools.py)
_write_lock = asyncio.Lock()
_read_semaphore = asyncio.Semaphore(10) # Max 10 parallel reads

async def async_read_file(path: str, **kwargs):
    async with _read_semaphore:
        return await asyncio.to_thread(sync_read_file, path, **kwargs)

async def async_write_file(path: str, content: str, **kwargs):
    async with _write_lock:
        return await asyncio.to_thread(sync_write_file, path, content, **kwargs)

9. Memory Management & Token Compaction (`memory/`)

Long-running agent sessions naturally accumulate substantial turn history, leading to token exhaustion and elevated API costs. BareMinimum solves this through active context window management.

Token Counting (`memory/token_counter.py`)

Uses tiktoken with the cl100k_base encoding to calculate exact token consumption for incoming prompts, system definitions, tool schemas, and conversation histories.

Sliding Window Compaction (`memory/compaction.py`)

When current history tokens exceed the threshold percentage (default: 70% of model window):

  1. Preserves System Instruction Prompt and initial user task objective.
  2. Retains the most recent N turns (defined by KEEP_RECENT=6) to preserve current operational context.
  3. Summarizes older intermediate tool exchanges into a single compact context summary message.
  4. Prunes duplicate tool schemas and redundant file read outputs from history.

10. LLM Engine, Resilience & OAuth 2.0 (`llm/`, `auth/`)

Multi-Provider LLM Abstraction (`llm/llm_client.py`)

Provides a standardized interface for sending prompts and receiving tool call structures across leading model families:

  • Gemini 3.6 Flash
  • Claude Opus 4.8
  • DeepSeek V4.1 Flash
  • GLM 5.3 Flash

Exponential Backoff & Resilience

API network calls are wrapped in automated retry handlers with exponential backoff and randomized jitter to handle rate limits (429) or transient provider outages seamlessly.

OAuth 2.0 Credentials Engine (`auth/oauth.py`)

For enterprise authentication, BareMinimum integrates OAuth 2.0 Client Credentials Grant workflows:

  • Retrieves Bearer tokens automatically from configured OAuth endpoints.
  • Caches tokens in thread-local storage with proactive buffer expiry refresh (e.g. refreshing 60s before token expiration).
  • Supports standard corporate proxy routing via USE_PROXY and HTTP_PROXY_URL settings.

11. Graph RAG Codebase Intelligence Subsystem (`graph/`)

To enable multi-repository codebase understanding beyond raw text search, BareMinimum includes an integrated Graph RAG indexing and retrieval engine:

AST Generation (`ast_generator.py`)

Parses source code into Abstract Syntax Trees to extract classes, interfaces, method signatures, annotations, and import structures.

Call Graph Building (`call_graph_generator.py`)

Maps caller-callee relationships across files and modules to trace function invocation hierarchies.

Doc Linking (`doc_linker.py`)

Links markdown architecture docs and API specifications directly to source code elements in the graph.

Neo4j Indexing & Retrieval (`neo4j_inserter.py`, `retrieve.py`)

Stores code relationships in Neo4j database, allowing the agent to query structural dependencies with >90% lower token footprint than reading raw files.
