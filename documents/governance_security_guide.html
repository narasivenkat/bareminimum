Governance & Security Status Guide — BareMinimum Harness

Comprehensive Audit of Implemented Security Mechanisms and Remaining Governance Enhancements

1. Executive Summary

The bareminimum harness is a model-agnostic, lightweight agentic framework capable of autonomous codebase exploration and file modification. It combines Microsoft AutoGen sub-agent patterns, parallel tool execution, context compaction memory, and serialized file updates.

To support enterprise deployment, key governance and security features are already built directly into the core framework:

  • Indirect Prompt Injection Defense: Keyword scanning and boundary encapsulation with <untrusted_file_content> XML tags.
  • Human-in-the-Loop (HITL) Write Approvals: Interactive diff previews and user confirmation gates (y/N) for disk mutations.
  • Structured Audit Logging & Masking: JSON logging with regex-based redaction of Bearer tokens, secrets, API keys, and email addresses.
  • LLM Retry & Backoff Engine: Exponential backoff retry loop handling transient API errors and rate limit throttling.
  • Runtime Environment Secret Overrides: Environment variable precedence over configuration files for OAuth credentials.
  • Context Memory Compaction & Cost Tracking: Automatic conversation history summarization and cumulative USD cost tracking.
  • Multi-Agent Execution Concurrency Safety: Parallel read task dispatch alongside mutex-locked sequential write operations.
  • Workspace Path Containment: Path containment checks ensuring tool calls stay within HARNESS_WORKSPACE.

This document details all currently implemented features alongside the remaining gaps and planned enhancements required for full enterprise production compliance.

4. Governance & Security Features Currently Existing in BareMinimum

Status: The following 8 security and governance capabilities are fully implemented in the codebase with unit test coverage.

4.1 Indirect Prompt Injection Detection & XML Boundary Encapsulation

Location: tools/tool_output_sanitizer.py, tools/registry.py, orchestrator/tools.py

When codebase files or search results are fetched via tools, raw outputs are sanitized before being placed into the LLM message history:

  • Pattern Matching: Scans content against INJECTION_PATTERNS (e.g. "ignore all previous instructions", "system override", "you are now an unrestricted...", "disregard above").
  • Security Warning Injection: Prepends [SECURITY WARNING: Possible prompt injection detected in file content] whenever a matching pattern is triggered.
  • Boundary Tag Protection: Wraps output in explicit <untrusted_file_content path="...">...</untrusted_file_content> XML tags, escaping inner closing tags to prevent model boundary escapes.

4.2 Human-in-the-Loop (HITL) Controls & Diff Previews

Location: tools/write_file/__init__.py

To prevent accidental, unauthorized, or malformed codebase modifications, all file modification tools (write_file and its alias create_file) enforce Human-in-the-Loop (HITL) verification and approval gates before committing changes to disk.

4.2.1 Core Implementation Mechanics

  • Unified Diff Generation: Evaluates proposed updates against existing file content using Python's difflib.unified_diff. The diff compares a/<rel_path> and b/<rel_path>, rendering line-by-line additions (+) and deletions (-).
  • Interactive User Confirmation: When interactive=True (default), prints the unified diff preview to the console and halts execution with the approval prompt: Approve file write to '<path>'? [y/N]: . Inputs matching y or yes allow execution to proceed (status: "approved_and_written"). Any other response raises a PermissionError and aborts the write.
  • Non-Interactive / Headless Fail-Safe: In non-interactive environments (CI/CD pipelines, headless runners, or EOF/closed STDIN streams), attempts to prompt user input trigger an EOFError or OSError. These exceptions are caught and raised as PermissionError("User rejected write operation... (non-interactive input / EOF)"), preventing headless background processes from making unverified file writes.
  • Dry-Run Simulation Mode: When dry_run=True is passed, the tool computes and returns the unified diff preview without modifying disk (status: "dry_run_simulated", bytes_written: 0). This allows agents or automated test suites to simulate file edits risk-free.

4.2.2 Tool Schema & Parameter Reference

Parameter Name Type Default Governance Function
path str Required Workspace-relative target file path (validated via resolve_path).
content str Required Full text payload proposed for file writing or replacement.
overwrite bool True Controls whether existing files can be overwritten. Raises ValueError if False and file exists.
interactive bool True Enforces interactive human confirmation gate before modifying disk.
dry_run bool False Simulates file mutation and outputs unified diff without modifying disk.

4.2.3 Multi-Agent Concurrency & Mutex Synchronization

In multi-agent environments or Orchestrator mode, multiple sub-agents may propose write operations simultaneously. To prevent terminal output collisions, scrambled diff previews, or race conditions during user input prompts, orchestrator/tools.py routes all file writes through a global asyncio.Lock() write mutex (_write_lock). This guarantees that HITL approval prompts are presented sequentially one at a time.

4.3 Structured JSON Audit Logging & PII/Secret Redaction

Location: log/log.py

All logging throughout the harness uses get_logger() / get_audit_logger(), backed by MaskingJsonFormatter:

  • Structured JSON Output: Emits formatted JSON objects containing timestamps, log levels, logger names, and message payloads suitable for SIEM ingestion.
  • Regex Redaction: Automatically redacts sensitive patterns:
    • Bearer tokens → Bearer [REDACTED_TOKEN]
    • API keys, client secrets, passwords → [REDACTED_SECRET]
    • Email addresses → [REDACTED_EMAIL]

4.4 LLM Exponential Backoff Retry Strategy

Location: llm/llm_client.py

Protects model completion requests against transient network failures and API rate limit throttling:

  • Configurable Retries: Reads RETRY.MAX_RETRIES (default: 3), INITIAL_BACKOFF (0.5s), MAX_BACKOFF (8.0s), and BACKOFF_MULTIPLIER (2x) from configuration.
  • Graceful Degradation: Catches API exceptions, logs backoff delays, and retries up to the maximum threshold before raising structured exceptions.

4.5 Environment Variable Credentials Override

Location: auth/oauth.py

Prioritizes environment variables (LLM_OAUTH_CLIENT_ID, OAUTH_CLIENT_ID, LLM_OAUTH_CLIENT_SECRET, OAUTH_CLIENT_SECRET, OAUTH_TOKEN_URL, LLM_OAUTH_SCOPE, OAUTH_SCOPE) over values stored in resources/config.yaml, allowing secure secret injection at runtime.

4.6 Context Window Memory Compaction & Token/Cost Calculation

Location: memory/compaction.py, memory/token_counter.py, loop/loop.py

Prevents context overflow while tracking session resource usage:

  • Token Counter: Uses tiktoken (with character/4 fallback) to count prompt and completion tokens.
  • Context Memory Compactor: Automatically summarizes older assistant and tool messages when conversation token length exceeds THRESHOLD_PCT (default: 70%) of model context window, keeping system prompts and recent turns intact.
  • Monetary Cost Estimator: Computes cumulative USD cost using configured per-model pricing (e.g. INPUT_COST_PER_1M and OUTPUT_COST_PER_1M) and returns totals in AgentResult.

4.7 Multi-Agent Concurrency & Mutex Write Safety

Location: orchestrator/orchestrator.py, orchestrator/tools.py

Ensures safe multi-agent workload distribution:

  • Parallel Read Task Execution: Concurrently dispatches read operations (read_file, list_dir, file_search) using thread pools and asyncio.Semaphore(10) to throttle execution.
  • Mutex Write Gate: Enforces serialized file mutations using an asyncio.Lock() write mutex (_write_lock) across sub-agents to prevent race conditions or corrupted overwrites.

4.8 Workspace Path Resolution & Containment

Location: tools/_common.py

Resolves relative and absolute file paths against HARNESS_WORKSPACE (or the project root) and validates path containment using candidate.relative_to(root) to block standard relative path traversal attempts (e.g., ../../etc/passwd).

6.1 Prompt Injection Sanitizer (tools/tool_output_sanitizer.py)

import html
import re

INJECTION_PATTERNS = [
    r"ignore\s+(all\s+)?previous\s+instructions",
    r"system\s+override",
    r"you\s+are\s+now\s+an?\s+unrestricted",
    r"disregard\s+above",
]

def sanitize_tool_output(content: str, path: str = "") -> str:
    for pattern in INJECTION_PATTERNS:
        if re.search(pattern, content, re.IGNORECASE):
            content = f"[SECURITY WARNING: Possible prompt injection detected in file content]\n" + content
            break

    safe_content = content.replace("</untrusted_file_content>", "&lt;/untrusted_file_content&gt;")

    return (
        f'<untrusted_file_content path="{html.escape(path)}">\n'
        f'{safe_content}\n'
        f'</untrusted_file_content>'
    )

_write_lock = asyncio.Lock()

async def async_write_file(filepath: str, content: str, ...) -> str:
    async with _write_lock:
        logger.info("[Orchestrator Write Lock Acquired] Writing file: %s", filepath)
