Evaluating & Benchmarking Agent Coding Harnesses

A comprehensive engineering guide on BareMinimum setup and CLI operation, test suite setup and datasets, benchmark parameter calculation formulas, sandbox architectures, and evaluation implementation patterns.

Architecture & Benchmarking
Target Audience: AI Engineers, System Architects, QA Lead
Status: Production Standard

01 Overview & Core Concepts

Evaluating an Autonomous AI Coding Agent Harness requires moving beyond static LLM text benchmarks (like perplexity or single-prompt code completion). An agent coding harness is an interactive system comprising an LLM backbone, tool orchestration, context window management, feedback integration loops, state persistence, and sandbox execution environments.

Benchmarking an agent harness evaluates not just the raw intelligence of the model, but the end-to-end efficiency, safety, correctness, and resource consumption of the agent system while navigating complex software repositories and multi-turn execution loops.

Model Evaluation vs. Harness Evaluation

Model Evaluation: Tests next-token prediction, code syntax completion, or isolated function generation (e.g., HumanEval). Measures model capabilities without tool interactions.

Harness Evaluation: Tests multi-file navigation, file editing precision, shell command execution, error diagnosis, tool selection adherence, state recovery, and sandbox compliance across hundreds of agent turns.

Why Rigorous Benchmarking Matters

Regression Prevention: Ensures system prompts, tool schemas, or context truncation logic updates do not degrade coding capabilities.

Cost & Latency Optimization: Quantifies token usage and wall-clock execution time per solved repository issue.

Governance & Safety: Validates sandbox containment and refusal of prompt injections embedded in external codebases.

💡 Key Architectural Realization

A superior underlying LLM inside a poorly designed agent harness (with noisy tool outputs, poor context window pruning, or high tool error rates) will underperform a modest LLM operating inside a highly optimized agent harness.

2.3 Modes of Operation

BareMinimum supports four distinct operational execution modes:

Execution Mode Invocation Command Description & Key Workflow
1. Interactive REPL Mode runmin
or python run.py		 Starts an interactive CLI prompt where you can issue sequential coding tasks, inspect tool calls, and review HITL diff previews.
2. Direct Command Line Mode runmin "task"
or python run.py "task"		 Executes a single non-interactive task directly from terminal arguments and outputs final results upon completion.
3. Interchangeable Shell / Bash Mode Type /bash at task prompt
or runmin /bash		 Enters OS shell execution mode (`bash>`). Commands run directly in terminal. Running cd path/ dynamically updates HARNESS_WORKSPACE for LLM tools. Return via exit or quit.
4. Model Switching (`/model`) Type /model at prompt
or runmin /model		 Displays active model selection dialog. Switch dynamically between gemini-3.6-flash, claude-opus-4.8, deepseekv41-flash, and glm-5-3-flash.
5. Orchestrator Mode (`/orchestrator`) Type /orchestrator at prompt Activates AutoGen parallel read execution across sub-agents while routing write calls through the serialized write queue mutex.

2.4 Agent Execution Loop Mechanics

The core execution spine (loop/loop.py) operates as follows:

  1. Prompt Evaluation: Seeds conversation history with system prompt and user request.
  2. Model Turn: Invokes LLM callable passing current message history and available tool JSON schemas.
  3. Narration Requirement: Enforces that tool call assistant messages include plain-text narration explaining tool purpose (e.g. "Reading loop.py to inspect loop logic").
  4. Parallel Tool Execution: Intercepts read-only tool calls (read_file, list_dir, file_search) and dispatches them concurrently via orchestrator/tools.py.
  5. HITL Approval Gate: Intercepts write tool calls (write_file) and presents line-by-line unified diff previews (difflib.unified_diff) for human user approval (y/N).
  6. Sanitization & Encapsulation: Wraps tool outputs in <untrusted_file_content path="..."> XML tags and prepends security warnings if prompt injection patterns are detected.
  7. Memory Compaction: Triggers sliding-window context summarization (memory/compaction.py) when prompt tokens exceed configured threshold percentage (default 70%).
  8. Termination: Concludes when model returns text without tool calls (STOP_FINAL_ANSWER) or forces plain text reply if turn limit is reached (STOP_MAX_TURNS).

💡 Sandbox Isolation Best Practice

Always run evaluation test suites with disabled network access (--network none) and strict memory/CPU constraints to prevent sandbox escaping, external API dependency leaks, or invalid network calls during test execution.

Common Test Setup Troubleshooting

  • Path Containment Assertion Errors: If file tool tests fail with path containment errors, ensure HARNESS_WORKSPACE is explicitly pointing to a valid resolved path inside your temporary test directory (e.g. tmp_workspace).
  • Non-Interactive Stream Rejection: Interactive write tests require mocked stdin/stdout streams. When testing write_file or HITL approval, mock input using monkeypatch.setattr('sys.stdin', io.StringIO('y\n')).
  • Missing Module Errors: Ensure virtual environment is activated and dependencies are installed via pip install -r requirements.txt.

04 How to Compute Benchmarking Parameters

To evaluate agent performance scientifically, key performance indicators (KPIs) must be computed using precise mathematical formulas and data captured during agent execution.

4.1 Task Correctness Parameters

1. Resolved Rate (% Pass)

The percentage of benchmark repository tasks where the code patch generated by the agent successfully passes all verification unit tests.

Resolved Rate (%) = ( N_resolved / N_total ) * 100%

Where:
  N_resolved = Number of benchmark tasks passing verification test suite (returncode == 0)
  N_total    = Total number of benchmark tasks evaluated

2. Pass@k Metric

The probability that at least one candidate patch generated out of $k$ trials per problem passes the evaluation test suite.

Pass@k = E [ 1 - ( (n - c) choose k ) / ( n choose k ) ]

Where:
  n = Total candidate sample runs generated per problem task (n >= k)
  c = Number of correct candidate runs that pass verification pytest suite
  k = Number of evaluated samples per problem (typically k=1 or k=5)

4.2 Token Economics & Monetary Cost ($ USD) Parameters

Token tracking and monetary cost calculations are implemented in memory/token_counter.py using the TokenTracker dataclass.

1. Token Counting Engine

Input and output tokens are counted per turn using tiktoken (with cl100k_base BPE encoding) or character fallback heuristic:

# Character Fallback Heuristic when tiktoken is unavailable:
Tokens_estimated = ceil( Character_Length / 4.0 )

2. Cost Calculation Formula

Cumulative session cost in USD is calculated by applying model-specific per-million token pricing rates from resources/config.yaml:

Total Cost ($ USD) = ( ( Input_Tokens / 1,000,000 ) * Input_Cost_Per_1M ) 
                   + ( ( Output_Tokens / 1,000,000 ) * Output_Cost_Per_1M )

Model Pricing Matrix (Configured Rates)

Model Identifier Input Cost per 1M Tokens (USD) Output Cost per 1M Tokens (USD) Context Window Size
gemini-3.6-flash (Default) $0.15 $0.60 128,000 tokens
claude-opus-4.8 $15.00 $75.00 200,000 tokens
deepseekv41-flash $0.14 $0.28 64,000 tokens
glm-5-3-flash $0.10 $0.20 128,000 tokens

4.3 Execution Efficiency Parameters

1. Average Turns to Resolve

Measures the mean number of interaction turns required by the agent loop (loop/loop.py) before returning a final answer:

Avg Turns = ( Sum of Turns across all resolved tasks ) / N_resolved

2. Wall-Clock Execution Duration

Total time elapsed from task initiation to completion, recorded in seconds:

Duration (seconds) = t_end - t_start

4.4 Tool Usage Quality Parameters

Schema Error Rate

Percentage of tool calls emitted by the model containing invalid JSON, missing required arguments, or unknown tool names:

Schema Error Rate (%) = ( N_tool_errors / N_tool_calls ) * 100%

Redundant Tool Call Ratio

Percentage of read/search tool calls that repeat previous searches without discovering new information:

Redundant Call Ratio (%) = ( N_duplicate_read_calls / N_read_calls ) * 100%

4.5 Parameter Data Flow inside `AgentResult` Dataclass

At the end of every task run, loop/loop.py aggregates and returns all benchmarking parameters inside an AgentResult object:

@dataclass
class AgentResult:
    final_text: str          # Final plain text response
    messages: List[Dict]     # Complete conversation message transcript
    turns: int               # Total turns executed
    stop_reason: str         # "final_answer" or "max_turns"
    tool_calls: int          # Total tool calls executed
    input_tokens: int        # Cumulative input/prompt tokens
    output_tokens: int       # Cumulative output/completion tokens
    total_cost: float        # Total calculated USD cost
    metadata: Dict[str, Any] # Contains compactions count and token metrics breakdown

07 Benchmark Harness Architecture Design

An enterprise-grade evaluation pipeline requires complete separation between the Evaluating Driver System and the Target Agent Execution Environment to prevent side-effects, resource leaks, or invalid state persistence.

Evaluation Harness Architecture & Execution Pipeline

Architectural Requirements

  • Ephemeral Sandbox Isolation: Each benchmark task runs inside an isolated, non-persistent container (e.g., Docker or Firecracker MicroVM) with strict resource limits (RAM: 4GB, CPU: 2 cores).
  • State Reset Strategy: Git workspace reset (`git clean -fdx && git reset --hard`) after every trial to eliminate cross-task contamination.
  • Network Partitioning: External internet access is blocked during evaluation to prevent test environment leakage, API call cheating, or retrieving online solutions.

08 Step-by-Step Implementation Guide

Below is a production Python implementation of an automated evaluation harness runner designed to execute agent tasks, verify output patches via pytest, and capture performance telemetry.

import time
import json
import subprocess
from pathlib import Path
from typing import Dict, Any, List

class AgentBenchmarkRunner:
    """
    Automated Evaluation Harness for Agent Coding Systems.
    Executes benchmark tasks, captures execution metrics, and computes pass/fail outcomes.
    """
    def __init__(self, dataset_path: str, agent_harness, output_dir: str = "./eval_results"):
        self.dataset_path = Path(dataset_path)
        self.agent_harness = agent_harness
        self.output_dir = Path(output_dir)
        self.output_dir.mkdir(parents=True, exist_ok=True)

    def load_benchmark_tasks(self) -> List[Dict[str, Any]]:
        """Loads task definitions (e.g., SWE-bench task objects)."""
        with open(self.dataset_path, "r", encoding="utf-8") as f:
            return json.load(f)

    def run_eval_suite(self) -> Dict[str, Any]:
        """Executes full benchmark evaluation across all dataset tasks."""
        tasks = self.load_benchmark_tasks()
        results = []
        total_resolved = 0

        for task in tasks:
            task_id = task["instance_id"]
            print(f"[EVAL] Starting task: {task_id}")
            
            # 1. Setup Environment & Apply Base Commit
            self._prepare_task_workspace(task)

            start_time = time.time()
            
            # 2. Execute Agent Loop
            harness_result = self.agent_harness.run(
                problem_statement=task["problem_statement"],
                workspace_dir=task["workspace_dir"]
            )
            
            duration = time.time() - start_time

            # 3. Verify Solution via Automated Test Suite Execution
            is_resolved, test_output = self._verify_patch(task)
            if is_resolved:
                total_resolved += 1

            # 4. Record Task Metrics
            task_metric = {
                "instance_id": task_id,
                "resolved": is_resolved,
                "duration_seconds": round(duration, 2),
                "total_turns": harness_result.get("turns", 0),
                "total_tokens": harness_result.get("total_tokens", 0),
                "tool_calls": harness_result.get("tool_calls_count", 0),
                "tool_errors": harness_result.get("tool_errors_count", 0),
                "test_output_snippet": test_output[:500]
            }
            results.append(task_metric)
            print(f"[EVAL] Completed {task_id}: Resolved={is_resolved} in {round(duration, 1)}s")

        # 5. Compute Aggregate Benchmark Summary
        resolved_rate = (total_resolved / len(tasks)) * 100.0 if tasks else 0.0
        summary = {
            "total_tasks": len(tasks),
            "total_resolved": total_resolved,
            "resolved_rate_percent": round(resolved_rate, 2),
            "avg_duration_seconds": round(sum(r["duration_seconds"] for r in results) / len(results), 2),
            "avg_tokens_per_task": round(sum(r["total_tokens"] for r in results) / len(results), 2),
            "detailed_results": results
        }

        self._save_report(summary)
        return summary

    def _prepare_task_workspace(self, task: Dict[str, Any]):
        """Resets repo to base commit state before agent run."""
        repo_dir = task["workspace_dir"]
        subprocess.run(["git", "clean", "-fdx"], cwd=repo_dir, check=True)
        subprocess.run(["git", "checkout", task["base_commit"]], cwd=repo_dir, check=True)

    def _verify_patch(self, task: Dict[str, Any]) -> (bool, str):
        """Runs validation test cases against modified workspace."""
        repo_dir = task["workspace_dir"]
        cmd = task.get("test_command", ["pytest", task["eval_test_path"]])
        res = subprocess.run(cmd, cwd=repo_dir, capture_output=True, text=True)
        passed = (res.returncode == 0)
        return passed, res.stdout + res.stderr

    def _save_report(self, summary: Dict[str, Any]):
        report_file = self.output_dir / f"benchmark_report_{int(time.time())}.json"
        with open(report_file, "w", encoding="utf-8") as f:
            json.dump(summary, f, indent=2)
        print(f"[EVAL] Benchmark Report saved to {report_file}")

09 Best Practices, Pitfalls & Anti-Patterns

Common Pitfalls to Avoid

  • Data Contamination / Memorization: LLMs trained on public GitHub repos may memorize benchmark unit test answers. Use temporal cutoff filtering or freshly created internal evaluation datasets.
  • Flaky Test Suites: Unstable test environments distort Pass@1 metrics. Always pre-validate test deterministic repeatability (10 clean baseline executions).
  • Unbounded Loop Costs: Agents stuck in infinite retry loops consume massive token budgets. Always enforce hard bounds (`max_iterations`, `max_tokens_per_run`).

Industry Best Practices

  • Progressive Evaluation Filtering: Run light syntax/lint checks first before spending resources on deep multi-file repo runs.
  • Structured Telemetry Traps: Capture exact JSON traces of tool input/outputs to identify agent stuck points.
  • Pairing Automated with Human Grading: Combine automated pytest suites with periodic expert code review for architectural elegance and security analysis.
